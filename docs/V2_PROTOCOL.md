# FraudLens V2 development protocol

The V1 final test was evaluated before V2 began. It is a reused retrospective holdout. The V2 development command reads only the 472,432 rows in the original train and validation periods, aligns each row to the V1 partitions, and refuses cutoffs that enter the final-test range. The original 118,108 final-test rows and labels are unavailable to development, including preprocessing, weighting, selection and calibration. A separate release is required after all final choices are written. V1 remains immutable.

## Populations and selection

- Reserve the last 10% of the V2 development prefix as a chronological decision-policy and calibration block. All cuts extend to the end of an equal-second group.
- Use three expanding-window folds within the preceding development prefix. Nominal boundaries, as fractions of all development rows, are train/validation `0–45% / 45–60%`, `0–60% / 60–75%`, `0–75% / 75–90%`. Use every validation row and the same rows for direct comparisons. Deterministic sampled training for costly methods is labeled as a separate budget. Evaluate those methods on the same full validation blocks whenever possible, with matched training references.
- Primary selection is the unweighted mean of the three validation average precisions (AP). Report fold variability with population standard deviation. ROC-AUC is secondary. Promote only when mean AP strictly improves, mean AUC declines by at most 0.01, and at least two folds gain AP. When initialized, the exact V1 XGBoost recipe is the comparison reference. Keep rejected trials and Pareto candidates.
- The preliminary validation tables report every threshold-dependent metric at the fixed score 0.5 for probability-like outputs and 0 for decision margins. For the final freeze, select one learned operating threshold on the first half of the reserved block after fitting any calibrator on a separate earlier chronological interval as available. Report policy metrics on the later reserved half. Calibration comparisons use disjoint calibration-fit and evaluation intervals. Do not interpret uncalibrated weighted model scores as probabilities. The later review policy must be frozen before retrospective evaluation.
- Keep natural prevalence in all evaluation rows. Top 1%, 5%, 10% review budgets rank continuously and break ties by original source order. Per-fold reports include accuracy, AP, ROC-AUC, precision, recall, F1, specificity, confusion counts, runtimes and budgets. Save out-of-fold scores locally and checkpoint every completed fold. Seed 42 and six CPU threads are the initial configuration.

## Feature audit and search sequence

Load TransactionAmt, ProductCD, card, address, distance, email, device, C1–C14, D1–D15, M1–M9, V1–V339 and id_01–id_38. Raw transaction ID, elapsed seconds and labels are metadata. Learn no vocabulary from future rows. Feature-cache categorical codes use first appearance and expose only the categories in each training prefix. Held-out new categories become missing. Boosters retain native numeric missingness. Anonymized fields are treated as provided record fields, with unverified real-world availability semantics. Compare ablations that drop anonymized blocks and document that limitation. No cross-row target aggregates or competition-test transduction.

Start with the V1 XGBoost settings on the expanded raw feature matrix. Refit the V1 feature/encoding recipe on exactly the same folds for comparison. Then separate the effects of expanding coverage, categorical representation and past-only statistics before tuning. Give boosting families short sequential searches over depth/leaves, rounds, sampling, regularization, and train-derived versus unit weights. Benchmark Logistic Regression, GaussianNB, KNN, SVM, Decision Tree, Random Forest and AdaBoost with appropriate transforms and bounded training subsets, with matching references. Compare V1-style and richer NumPy and PyTorch architectures using validation AP. Record incomplete or resource-limited trials. Compare a simple mean and validation-weighted ensembles only after obtaining aligned out-of-fold scores. Evaluate anomaly and exploratory patterns separately from supervised predictions.

Read the authors’ winning write-up and their analysis of card/address/D1 groupings. They motivate checking whether a partial card signature plus a row-local D offset can retain a useful approximate identity, and checking temporal drift by feature group. V2 must compute every historical statistic from strictly earlier transactions. It does not copy the authors’ transductive aggregation, future-side cross-validation or competition leaderboard thresholds. These competition ROC values do not define an attainable V2 AP.
