# FraudLens final experiment protocol

Freeze this protocol before training or opening the full chronological holdout. The project uses seed 42 and defaults to six CPU threads. Record the source file and configuration hashes, installed dependencies, resource snapshot and timestamp in the local `artifacts/full/protocol_freeze.json` before computation.

## Data and information boundaries

Use all 590,540 labeled transactions from IEEE-CIS and attach the identity fields with a validated one-to-one left join. The development run uses the first approximately 100,000 transactions and keeps timestamp groups intact. Sort by relative elapsed seconds and split about 60/20/20, moving cutoffs forward as needed to preserve timestamp groups. Before training, compare only IDs and elapsed seconds to verify that the full holdout starts after the quick dataset and shares no transaction IDs with it.

Use selected card, address, product, email-domain and device inputs, amount, log amount and the identity-join-missing indicator. Transaction ID, elapsed time and entity key are metadata. The four-component card/address key is a proxy. A history can use only strictly earlier seconds. One-hour and 24-hour windows include the lower boundary. An incomplete entity key receives a cold start. Missing, invalid or undefined quantities stay missing with explicit defaults for counts. Continue accumulating observed history across all partitions without fraud labels. Training alone fits model imputation, category caps, encoding and scaling. Basic and behavioral XGBoost differ only in the presence of the seven historical inputs.

Phase 1 validates and stores the labels during preparation, including the partition class counts in the private manifest. The training pipeline suppresses the holdout prevalence in the pre-release log. No final target record or label summary is inspected for fitting, selection, troubleshooting or documentation prior to the release. Core, PyTorch MLP, anomaly/risk, DBSCAN/Apriori and supplementary/scratch stages run serially. Fit and validation stages yield before loading test. The pipeline records checkpoint and selection file hashes in `holdout_release.json` before opening test. The test consumes previously frozen choices and a predeclared stratified supplementary sample only. If a defect requires a rerun after release, record it and its impact.

## Frozen model and evaluation choices

- Core models: majority dummy; balanced LBFGS Logistic Regression (500 iterations); balanced Random Forest (120 trees, depth 12, minimum leaf four); histogram XGBoost (240 trees, depth 5, learning rate 0.075, min child weight four, row subsample 0.85, column subsample 0.8, 128 bins). Both XGBoost fits use the train negative-to-positive ratio. No search is planned. Core selection is best validation AP among learned candidates, with ties favoring Logistic Regression, Random Forest, then XGBoost. Behavioral XGBoost is the designated deployed model from development. If the validation rule selects another classical model, stop and report the conflict before opening test.
- Thresholds maximize validation F1, with highest threshold on ties and `score >= threshold`. Dummy uses its most-frequent-class rule. Report AP as the primary metric, ROC-AUC, precision, recall, specificity, F1, accuracy, confusion counts and PR/ROC curves on the same full validation and final-test rows. Record fitting and scoring times separately. Times exclude time suspended at the release step. Scoring excludes preprocessing and metric calculation. Core timings measure positive-score inference and neural timings measure one scored batched pass, which also accumulates the weighted loss.
- The main CPU MLP uses the fitted behavioral preprocessor, sparse matrices and float32 dense batches of 512. The two hidden layers have 128 and 64 units, each with batch normalization, ReLU and dropout 0.25. The weighted BCE uses the training negative-to-positive ratio. Adam uses learning rate 0.001 and weight decay 0.0001, with at most 30 epochs, patience five and the earliest best validation AP checkpoint. Compare with the core benchmark on the exact same held-out rows. This neural experiment does not determine the deployment classifier.
- Isolation Forest fits meaningful numerical inputs on a bounded 60,000-row training sample. Negative `score_samples` values rank higher for more unusual activity. Score all training rows for the fixed midrank percentile reference. Compare classifier, anomaly and fixed `100 × (0.8 × classifier score + 0.2 × anomaly percentile)` using AP, ROC-AUC and precision and recall at the top 1%, 5% and 10% of reviews. Rank validation first and report the unchanged policy on the final holdout. Fixed priority boundaries are 40 and 75. Exact TreeSHAP explains the XGBoost raw margin using up to 2,000 validation rows globally. Compare local contributions plus expected value with the raw margin and sigmoid of that margin with the saved classifier score.
- DBSCAN receives a uniform 12,000-row training sample with the existing standardized behavioral inputs, radii 0.45/0.65/0.85/1.05, minimum samples 10/20, eight-million neighbor-link limit, and at most 1,500 non-noise rows for silhouette. Select by highest silhouette within the predeclared noise and cluster concentration limits, using the existing fallback for degenerate results. Two-component PCA is for visualization. Fraud labels describe clusters after fit. Apriori uses at most 30,000 uniform training rows and training-fitted conditions. Minimum support is 0.001 and confidence 0.05, with at least 100 antecedent matches and 30 fraud matches. A rule has up to three antecedents. Measure discovered rules on full validation.
- Supplementary classifiers and NumPy/reference networks share a stratified 20,000-row training sample and 4,000 rows from each evaluation partition. Sampling stays within each partition and preserves source order. Keep the existing model-specific weights, sparse or bounded dense matrices and KNN scoring batches. Report the matched subset separately from primary benchmarks. The scratch linear and 32-unit ReLU variants and references retain the existing weighted objective and validation checkpoint, finite-difference and matched-PyTorch checks.
- The Investigator examples are selected after release from saved final-test outcomes with deterministic chronological and anomaly tie rules. They are curated demonstrations. The release documents and public visuals omit transaction-level data. Keep local model binaries, observations, prediction artifacts and private screenshots under the ignored artifact directory.
